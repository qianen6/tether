## 1. 根 Cargo.lock 由 T10 同步（构建元数据，不涉及契约）

`crates/server/Cargo.toml` 直接引用工作区已预取的 `sha2` 和 `subtle`：

- `sha2`：server 只缓存令牌 SHA-256 摘要，用于当前进程内已撤销令牌的区分，不缓存明文令牌。
- `subtle`：32 字节配对密钥的常量时间比较。

请 T10 在根 Cargo.lock 的 `tether-server` dependencies 中增加：

```text
"sha2 0.11.1",
"subtle",
```

这些包及版本已存在于原始 Cargo.lock / 本机缓存，没有引入新版本或网络下载。本任务的 cargo 离线命令会自动更新上述包依赖边，验收后恢复根 lockfile 的原始内容，仅提交 server 与本请求文件。`--locked` 的统一验收应在 T10 完成同步后执行。

## 2. 持久化的 revoked / invalid_token 区分（待明确，不影响撤销失效）

冻结 Store 接口的 `revoke_device` 删除设备，`device_by_token` 对已删除令牌返回 None；接口没有撤销摘要/墓碑查询。现有 server 行为：

- 当前进程已认证/签发且随后撤销的令牌：`rejected(reason = revoked)`。
- server 重启之后，或当前进程尚未观察过其令牌就被删除的设备：`rejected(reason = invalid_token)`。
- 两者均关闭 4401；已建立连接全部关闭；revoke 返回原 Device（含 phone_key），由 host 调用 tunnel.revoke。

建议 T10 明确允许上述理由降级；若产品要求跨重启也严格返回 revoked，请扩展存储查询为包含撤销状态的令牌查找，或提供持久化令牌摘要墓碑查询。T03 不自行变更冻结签名，也不在 server 另建一份设备数据库。
